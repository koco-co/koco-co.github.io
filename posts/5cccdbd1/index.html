大模型应用开发(一)入门路线

发表于2026-08-29|更新于2026-09-02|Learn Topic大模型应用开发
|总字数:1.1k|阅读时长:3分钟
大模型应用开发 文章进度
  1. 01大模型应用开发(一)入门路线

课程目标

使用 Python、curl 和官方 SDK 调用八家厂商接口，构建带结构化输出、RAG、错误处理和成本观测的应用。

课程范围：API基础与适配、厂商调用、Prompt与输出、状态、RAG与可靠性。正式文章分别通过图解、实验和可观察证据完成学习闭环。

前置条件

建议具备 Python 3、命令行、Git 和基本 HTTP/JSON 能力；缺少的部分在相关阶段补齐。所有实验优先使用本地夹具，真实服务仅由读者显式配置。

学习路径

    flowchart TD
  P1[API基础与适配]
  P2[厂商调用]
  P3[Prompt与输出]
  P4[状态、RAG与可靠性]
  P1 --> P2
  P2 --> P3
  P3 --> P4

按阶段顺序阅读：API基础与适配 → 厂商调用 → Prompt与输出 → 状态、RAG与可靠性。每篇以实验输出或验收表判断是否可以继续。

文章安排

顺序 文章 解决的问题 前置 状态
1 大模型应用开发(一)入门路线 使用 Python、curl 和官方 SDK 调用八家厂商接口，构建带结构化输出、RAG、错误处理和成本观测的应用。 无 入口
2 大模型应用开发(二)API与密钥 能安全配置 API Key，理解请求、响应、限流、超时和错误。 AI与大模型基础：Token与Embedding 未开始
3 大模型应用开发(三)Provider适配 能把不同厂商映射到统一内部模型，同时保留原生能力和差异。 API与密钥 未开始
4 大模型应用开发(四)OpenAI、Anthropic与Gemini 能选择一个统一任务的主入口，读取 Responses、Messages、generateContent 与 Interactions 的关键 schema 差异，并把兼容入口放入迁移路径；不把每个 Provider 写成独立教程。 Provider适配 未开始
5 大模型应用开发(五)xAI、DeepSeek与Kimi 能分别识别 xAI Chat（messages/choices）与 xAI Responses（input/output），再比较 DeepSeek、Kimi 的兼容入口、模型字段和流式差异。 Provider适配 未开始
6 大模型应用开发(六)GLM与Qwen 能调用 GLM、Qwen 的官方入口，并区分兼容 API、原生 SDK 和模型服务。 Provider适配 未开始
7 大模型应用开发(七)Prompt与任务契约 能编写包含角色、输入、约束、输出和验收条件的 Prompt。 API与密钥 未开始
8 大模型应用开发(八)结构化输出与工具调用 能约束 JSON 输出，校验参数并安全执行函数或工具。 Prompt与任务契约 未开始
9 大模型应用开发(九)流式与错误 能处理 SSE、事件顺序、部分结果、超时、重试和取消。 结构化输出与工具调用 未开始
10 大模型应用开发(十)状态、Context与缓存 能管理多轮对话、上下文预算、摘要、缓存和会话恢复。 流式与错误 未开始
11 大模型应用开发(十一)多模态与文件 能处理图片、文档和文件输入，并验证 MIME、大小、权限和结果。 结构化输出与工具调用 未开始
12 大模型应用开发(十二)RAG与引用 能完成切分、Embedding、检索、重排、引用和答案校验。 Token与Embedding；状态、Context与缓存 未开始
13 大模型应用开发(十三)可靠性、成本与观测 能记录延迟、Token、成本、失败率和质量信号，并设计降级策略。 状态、Context与缓存；RAG与引用 未开始
14 大模型应用开发(十四)项目实战 构建一个多 Provider、结构化输出、RAG、错误恢复和成本观测的问答应用。 本系列前置主题文章（不含本篇） 未开始

开始学习

先完成环境检查，再从《大模型应用开发(二)API与密钥》开始。练习应保留输入、命令、输出、失败分类和复测条件；不要把在线调用结果当作本地实验的必需条件。
